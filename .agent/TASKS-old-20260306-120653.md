```

| 🔴 **HIGH** | Bundle has routes.yaml; framework manifest uses old pattern |

"NO `config/routes.yaml` file in the bundle."
```

**What needs doing:**

2. Verify no other code references this file (grep for `routes.yaml` in the codebase).

**Current file content:**
```yaml

controllers:
    resource:
        path: ../src/Controller/
        namespace: IM\Fabric\Bundle\HealthCheckBundle\Controller
    type: attribute
```

**After deletion:**
```bash

ls config/routes.yaml  # → No such file or directory
```

**Difficulty:** Easy

**How to test:**

**Unexpected outcomes:**

## T-06 — Add BUILD_START_TIME format validation

> **Status: Todo** ⏳ | **Severity: Medium** 🟡 | **Breaking Change** 💥

**Files:**
- `src/Controller/HealthCheckController.php` (method: `getBuildTimeForHumans()`)

**What the audit says:**
```
Section 8, Question 4 (Resolved):
Decision: ✅ ENFORCE milliseconds format with validation

Gap Analysis:
| **BUILD_START_TIME validation** | No validation; silently accepts seconds | 
| MUST validate and enforce milliseconds | 🟡 **MEDIUM** | Causes silent bugs |

Breaking Change #5:
Passing BUILD_START_TIME in seconds (10 digits) now throws InvalidArgumentException. 
Must be milliseconds (13 digits).
```

**What it means:**
The `getBuildTimeForHumans()` method currently accepts any timestamp value without validation. If a host application sets `BUILD_START_TIME` in seconds (10 digits, e.g., `1611915490`) instead of milliseconds (13 digits, e.g., `1611915490663`), the bundle silently accepts it but produces incorrect dates (year ~53000). This validation adds fail-fast behavior with a clear error message.

**What needs doing:**
1. Open `src/Controller/HealthCheckController.php`
2. Locate the `getBuildTimeForHumans()` protected method
3. After converting `$buildTimeUnix` to int, add validation checking if timestamp < 10000000000 (year 2286)
4. If validation fails, throw `InvalidArgumentException` with helpful message showing expected format
5. Keep existing intdiv($timestamp, 1000) logic for conversion
6. Update unit tests (T-05) to verify exception is thrown for 10-digit timestamps

**Before:**
```php
protected function getBuildTimeForHumans(): ?string
{
    $buildTimeUnix = $this->getParameter('app.build_start_time');

    if (!$buildTimeUnix) {
        return null;
    }

    try {
        return date(self::DATE_FORMAT_CODE, intdiv((int)$buildTimeUnix, 1000));
    } catch (\Exception) {
        return (string)$buildTimeUnix;
    }
}
```

**After:**
```php
protected function getBuildTimeForHumans(): ?string
{
    $buildTimeUnix = $this->getParameter('app.build_start_time');

    if (!$buildTimeUnix) {
        return null;
    }

    $timestamp = (int)$buildTimeUnix;

    // Validate: must be milliseconds (13 digits), not seconds (10 digits)
    // Any timestamp > year 2286 (9999999999 seconds) is likely in milliseconds
    if ($timestamp < 10000000000) {
        throw new \InvalidArgumentException(
            sprintf(
                'BUILD_START_TIME must be in milliseconds (got %d). '
                . 'Expected 13-digit timestamp (e.g., %d), not 10-digit seconds.',
                $timestamp,
                $timestamp * 1000
            )
        );
    }

    try {
        return date(self::DATE_FORMAT_CODE, intdiv($timestamp, 1000));
    } catch (\Exception) {
        return (string)$buildTimeUnix;
    }
}
```

**Difficulty:** Easy

**How to test:**
1. Apply the code change to `getBuildTimeForHumans()`
2. Create unit test: timestamp `1611915490` (10 digits) should throw `InvalidArgumentException`
3. Create unit test: timestamp `1611915490663` (13 digits) should return formatted date
4. Create unit test: verify exception message contains "milliseconds" and shows correct expected format
5. Run unit tests: `vendor/bin/simple-phpunit tests/Unit/Controller/HealthCheckControllerTest.php`
6. Manually test with test kernel setting seconds: `BUILD_START_TIME=1611915490 vendor/bin/simple-phpunit` should fail
7. Manually test with milliseconds: `BUILD_START_TIME=1611915490663 vendor/bin/simple-phpunit` should pass

**Unexpected outcomes:**
This is a **breaking change**. Any host application currently setting `BUILD_START_TIME` in seconds will start throwing exceptions when upgraded to v2. The exception will be thrown during controller instantiation or first call to `getBuildTimeForHumans()`, which may cause 500 errors if not caught. Consumers must update their build scripts from `date +%s` (seconds) to `date +%s%3N` (milliseconds). The magic number `10000000000` represents year 2286 - any legitimate timestamp before that year would fail validation, but this is acceptable for build timestamps which should always be recent.

**Enum implementation:**

```php
<?php

declare(strict_types=1);

namespace IM\Fabric\Bundle\HealthCheckBundle\Enum;

enum DatabaseType: string
{
    case DOCTRINE = 'Doctrine\\Bundle\\DoctrineBundle\\Registry';
    case MONGODB = 'Doctrine\\Bundle\\MongoDBBundle\\ManagerRegistry';
}
```

**Before (magic strings):**
```php
protected function testDatabaseConnection(): bool
{
    if ($this->manager === null) {
        return false;

        'Doctrine\\Bundle\\DoctrineBundle\\Registry' => $this->manager->getConnection()->connect(),

        default => false,
    };
}
```

```php
use IM\Fabric\Bundle\HealthCheckBundle\Enum\DatabaseType;

protected function testDatabaseConnection(): bool

        return false;
    }

        DatabaseType::DOCTRINE->value => $this->manager->getConnection()->connect(),
        DatabaseType::MONGODB->value => is_iterable(

        ),
        default => false,
    };
```

## Task 6: Add BUILD_START_TIME Validation

**Status:** Ready to start  
**Severity:** 🟡 MEDIUM  
**Estimated Time:** 30 minutes

### Action Required

Update `src/Controller/HealthCheckController.php` - modify `getBuildTimeForHumans()`:

```php
protected function getBuildTimeForHumans(): ?string
{
    $buildTimeUnix = $this->getParameter('app.build_start_time');

    if (!$buildTimeUnix) {
        return null;
    }

    $timestamp = (int)$buildTimeUnix;

    // Validate: must be milliseconds (13 digits), not seconds (10 digits)
    // Any timestamp > year 2286 (9999999999 seconds) is likely in milliseconds
    if ($timestamp < 10000000000) {
        throw new \InvalidArgumentException(
            sprintf(
                'BUILD_START_TIME must be in milliseconds (got %d). '
                . 'Expected 13-digit timestamp (e.g., %d), not 10-digit seconds.',
                $timestamp,
                $timestamp * 1000
            )
        );
    }

    try {
        return date(self::DATE_FORMAT_CODE, intdiv($timestamp, 1000));
    } catch (\Exception) {
        return (string)$buildTimeUnix;
    }
}
```

### Context

Gap Analysis identifies missing validation as MEDIUM severity. Currently silently accepts seconds, producing dates in year ~53000. Question 4 resolution requires fail-fast validation with clear error message.

**Breaking Change:** This is Breaking Change #5 - consumers passing seconds will get `InvalidArgumentException`.

```php
protected function testDatabaseConnection(): bool
```
